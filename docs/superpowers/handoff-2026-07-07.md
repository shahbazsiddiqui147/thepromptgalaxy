   "/c/Program Files/PuTTY/plink.exe" -ssh -batch -pw '<VPS_PASSWORD>' -hostkey "<HOST_KEY_FINGERPRINT>" root@46.250.239.74 "COMMAND HERE" 2>&1

## Key decisions already made — don't re-litigate these

- **Payload CMS is staying.** Verified directly against the npm registry: MIT licensed, no fees,
  no licensing concern. The "build our own CMS instead" idea was explored at length and explicitly
  abandoned in favor of building the frontend on top of the already-working Payload backend.
- **Full hierarchical URLs, all with trailing slashes:** `/subject/style/prompt-slug/` is the one
  canonical URL per prompt (Subject + Art Style are single-valued per prompt, so this is always
  unique — Tool is multi-valued, so it's deliberately excluded from the canonical path).
  `/style/[style]/` and `/tool/[tool]/` are separate archive pages linking back to that same
  canonical prompt URL, never a duplicate copy. Subject+Style combo pages (e.g. `/travel/cinematic/`)
  are gated behind a minimum-prompt-count threshold (currently 3) so thin/empty combinations don't
  get indexed.
- **Content Type is being converted from a hardcoded 2-option dropdown into a real admin-managed
  collection**, matching Subjects/Art Styles/Tools (add/edit/update/delete from the admin, no
  hardcoded values) — this is Tasks 1–4 of the plan.
- **No domain purchased yet — not needed to develop or test.** Deploy and verify against the VPS
  IP:port, exactly like the backend was.
- **Reference-image prompts are informational-only.** The site never handles a visitor's uploaded
  photo — that happens on the external AI tool (Midjourney, ChatGPT, etc.). The admin sets a
  `Reference Required` checkbox + a note field describing what kind of photo is needed; the
  frontend just shows this as a badge before the prompt text.
